# Конфигурация Tmux

[![Version](https://img.shields.io/github/v/tag/vhstack/tmuxpp?label=version&sort=semver&color=8aadf4)](https://github.com/vhstack/tmuxpp/tags)

[![CI](https://github.com/vhstack/tmuxpp/actions/workflows/ci.yml/badge.svg)](https://github.com/vhstack/tmuxpp/actions/workflows/ci.yml)

Эта конфигурация Tmux оптимизирует работу за счёт полезных сочетаний клавиш, поддержки True Color, работы с мышью и буфером обмена — без менеджера плагинов.  
Скрипт-пример `sample_run.sh` автоматически настраивает и запускает сессию с несколькими окнами.

![tmuxpp — сессии под контролем: окна, панели, copy/paste мышью](assets/sessions.gif)

Tmuxpp входит в [стек vhstack](https://github.com/vhstack/vhstack), где одна команда устанавливает полную рабочую среду (Prompt, Tmux, Neovim).

## 📥 Установка

### 1. Установите Tmux
Если Tmux ещё не установлен:
```sh
sudo apt install tmux   # Debian/Ubuntu
brew install tmux       # macOS
```
Дополнительную информацию можно найти в [**Tmux Wiki**](https://github.com/tmux/tmux/wiki).

### 2. Установите переменную TERM
Добавьте в файл `~/.bashrc`:
```sh
export TERM=xterm-256color
```

### 3. Клонируйте репозиторий и примените конфигурацию
```sh
git clone --depth 1 https://github.com/vhstack/tmuxpp.git ~/.tmux
rm -rf ~/.tmux/.git ~/.tmux/assets ~/.tmux/README*.md
ln -s ~/.tmux/tmux.conf ~/.tmux.conf
```
Файлы `clipboard.sh` и `install_win32yank.sh` должны остаться на месте — они нужны для работы с буфером обмена (см. ниже).

### 4. Только в WSL: быстрый буфер обмена
```sh
sh ~/.tmux/install_win32yank.sh
```
Настраивает `win32yank.exe` и ускоряет вставку примерно в четыре раза ([подробности](#win32yankexe-в-wsl)). На остальных системах не нужно.

## ⌨️ Сочетания клавиш

- **Клавиша Prefix**: `Ctrl + A` (вместо `Ctrl + B`)
- **Окна и панели:**
  - `Prefix + +` → Создать новую сессию
  - `Prefix + c` → Создать окно
  - `Prefix + ,` → Переименовать окно
  - `Prefix + $` → Переименовать сессию
  - `Prefix + |` → Разделить по вертикали (панели рядом)
  - `Prefix + -` → Разделить по горизонтали (панели друг под другом)
  - `Prefix + b` → Вынести панель в отдельное окно
  - `Prefix + x` → Закрыть панель
  - `Prefix + &` → Закрыть окно
  - `Prefix + s` → Дерево сессий, отсортированное по имени
- **Навигация:**
  - `Prefix + ←, →, ↑, ↓` → Переключаться между панелями
  - `Alt + →` / `Alt + ←` → Переключаться между окнами
  - `Ctrl + Alt + →` / `Ctrl + Alt + ←` → Перемещать окно
- **Изменение размера панелей:**
  - `Prefix + j/k/h/l` → Изменить размер панели (с повтором)
  - `Prefix + z` → Развернуть/восстановить панель
- **Мышь:**
  - Колесо → Прокрутка буфера истории (3 строки за щелчок; режим копирования включается автоматически и выключается внизу)
  - Перетаскивание → Выделение, при отпускании кнопки текст копируется в буфер обмена
  - Двойной / тройной щелчок → Скопировать слово / строку
  - Правый щелчок → Вставить из буфера обмена
  - `Prefix + m` → Включить/выключить поддержку мыши
  - `Prefix + >` или `Alt + правый щелчок` → Контекстное меню панели
- **Режим копирования (клавиши vi):**
  - `Ctrl + PageUp` или `Prefix + [` → Войти в режим копирования
  - `v` → Начать выделение, `y` → Скопировать, `q` → Выйти
  - `Prefix + ]` → Вставить из буфера tmux
  - История: 50 000 строк на панель
- **Перезагрузить конфигурацию:**
  - `Prefix + r`

## 📋 Буфер обмена

`clipboard.sh` связывает tmux с буфером обмена системы. Файл должен лежать рядом с `tmux.conf` (путь определяется при загрузке конфигурации, по умолчанию `~/.tmux/clipboard.sh`). Подходящая утилита определяется автоматически:

| Платформа | Утилита | Установка |
| --- | --- | --- |
| WSL / Windows | `win32yank.exe` (рекомендуется), иначе `clip.exe` / `powershell.exe` | `sh ~/.tmux/install_win32yank.sh` |
| macOS | `pbcopy` / `pbpaste` | уже есть в системе |
| Linux (Wayland) | `wl-copy` / `wl-paste` | `sudo apt install wl-clipboard` |
| Linux (X11) | `xclip` или `xsel` | `sudo apt install xclip` |

Копирование идёт сразу двумя путями: через локальную утилиту и через OSC 52. Второй путь это escape-последовательность, то есть текст едет в том же потоке, что и вывод на экран. Так он и попадает в буфер обмена той машины, за которой вы действительно сидите, в том числе через SSH и без единой утилиты на сервере. Нужен только терминал, который это умеет: Windows Terminal, WezTerm, kitty, iTerm2 и Alacritty умеют.

Обратно этот путь не ведёт. Терминал, который отдаёт свой буфер обмена по запросу, отдаёт его любой программе, которой позволено писать на экран. Хватило бы `cat` на подготовленный файл, чтобы прочитать, что там лежит. Поэтому терминалы отвечать отказываются, и для вставки нужна утилита на машине: `win32yank.exe` или `powershell.exe` в Windows, `pbpaste` в macOS, `wl-paste` или `xclip` в Linux. Если её нет, `clipboard.sh` возвращается к собственному буферу tmux, то есть к тому, что было выделено в tmux последним.

Варианты перебираются сверху вниз. Замеры сделаны в WSL (WSL2, Ubuntu, 20 прогонов):

| Операция | Путь | Время |
| --- | --- | --- |
| Копирование | `win32yank.exe` | 33 мс |
| | `iconv` + `clip.exe` | 33 мс |
| | OSC 52, работает всегда дополнительно | 5 мс |
| Вставка | `win32yank.exe` | 35 мс |
| | `powershell.exe Get-Clipboard` | 165 мс, при первом вызове 340 мс |
| | буфер tmux, если утилита не найдена | 3 мс |

К этому добавляется около 5 мс на сам вызов tmux. Копирование быстрое в любом случае. Дорого стоит только вставка без `win32yank.exe`. Чтобы использовать собственное выделение терминала, например через несколько панелей, удерживайте `Shift` при перетаскивании или отключите мышь через `Prefix + m`.

### win32yank.exe в WSL
Таблица выше показывает, для чего нужен `win32yank.exe`: для вставки, которая падает с примерно 175 мс до 45 мс. На копирование это не влияет — `clip.exe` сам лежит в `system32` и запускается так же быстро. Если путь через PowerShell вас устраивает, дальше читать не обязательно. Скрипт `install_win32yank.sh` всё настроит:
```sh
sh ~/.tmux/install_win32yank.sh           # установить
sh ~/.tmux/install_win32yank.sh --force   # скачать заново
sh ~/.tmux/install_win32yank.sh --remove  # удалить
```
Скрипт скачивает закреплённый релиз [win32yank v0.1.1](https://github.com/equalsraf/win32yank), проверяет SHA256 архива и самого `.exe` и кладёт утилиту в `%LOCALAPPDATA%\win32yank`, то есть в файловую систему Windows. Это сделано намеренно: если `.exe` лежит в файловой системе WSL, Windows загружает её через `\\wsl.localhost` и тратит более чем в два раза больше времени. В PATH попадает только символьная ссылка (`~/.local/bin`), а сам путь запоминается в `~/.cache/tmuxpp/win32yank.path`. После этого нажмите `Prefix + r`.

## 🎨 Цвет & Тема
- Включена поддержка True Color
- Доступные темы (через `@theme` в `tmux.conf`): `vhstack`, `vhstack_lite`, `catppuccin`
- Тема `vhstack` активирована по умолчанию

Конфигурация обходится без менеджера плагинов. Только опциональной теме `catppuccin` нужен плагин — клонируйте его один раз, затем `Prefix + r`:
```sh
git clone --depth 1 -b v2.1.3 https://github.com/catppuccin/tmux ~/.tmux/plugins/tmux
rm -rf ~/.tmux/plugins/tmux/.git
```
